Sixteen years ago when this book was written, the notion of creating a graphical user interface (GUI) must have seemed rather novel, particularly for someone from the world of Microsoft Windows, as the author was.  But the world of computing has moved on, and what seemed at that time “professional-appearing" windows and buttons seem now artifacts to be found in the San Jose Museum of Technology, amusing reminders of how far we have come and how rude our foundations now seem.The perl language is, itself, a powerful tool for doing a variety of file-related tasks, and now, in the year 2015, it is reasonable to expect that perl code snippets might be more useful if they were wrapped in some sort of GUI that allowed user input in a more modern technique than command-line responses. But tthe approach described in this book reminds me of efforts to learn assembly language for the 7600 bakc when I was a youthful programmer: possible, with considerable effort, but hardly a profitable exercise nowadays, with so many alternatives. I think Xcode, for example, with Swift, might be better. If you want to create a GUI then you should be able to use a GUI for the construction, something that Apple understood years ago with its various tools.A fatal shortcoming for me is that I live in a world of Macintosh computers. Although I was able to download and install the latest version of Tk, neithr the book nor my searching of the internet told me how to place the Tk files so that Perl could find them.
